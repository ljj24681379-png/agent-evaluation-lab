# Agent 评测实验室

> 从“模型回答得对不对”升级到“Agent 是否真正完成任务”。

一套面向生成式 Agent 的端到端评测方法，覆盖任务完成、工具调用、文件产物、稳定性、时延与失败修复。场景统一为脱敏的“办公成果生成 Agent”。

| 端到端运行 | 候选模型 | 正式任务 | 最高成功率 |
|---:|---:|---:|---:|
| **378** | **3** | **30** | **94.4%** |

[打开可视化 Demo](app/index.html) · [评测设计](docs/evaluation-design.md) · [失败分类](docs/failure-taxonomy.md) · [模型选型](docs/model-selection.md)

## 为什么做

传统模型评测常停在单轮回答质量，但 Agent 上线后还要回答：工具是否调用成功、文件是否真的可用、同一任务是否稳定、失败后能否修复、长尾时延是否可接受。因此，本项目将评测单元定义为一次完整交付，而不是一条回复。

## 核心指标

| 指标 | 定义与产品含义 |
|---|---|
| 端到端成功率 | 完整满足任务且成果通过校验的运行占比 |
| 工具失败率 | 出现工具选择、参数、执行或返回异常的运行占比 |
| 产物失败率 | 文件缺失、损坏、格式或关键内容不合格的运行占比 |
| 三次全成功率 | 同一任务三次运行全部成功的任务占比 |
| 平均耗时 / P95 | 日常体感速度 / 长尾等待风险 |
| 人评 A | 人工抽检中达到项目最高质量档的占比 |

> **单次成功不能代表真实稳定性。** 三次全成功率刻意提高门槛，用来暴露平均成功率掩盖的波动。

## 基线 vs 正式结果

优化加入四条约束：执行前识别全部交付物；交付前必须执行 `validate_artifact`；校验失败允许一次定向修复；未通过校验不得宣称完成。

`生成 → 直接交付` 变为 `生成 → 校验 → 定向修复 → 再校验 → 交付`。

| 模型 | 成功率 | 工具失败率 | 产物失败率 | 三次全成功率 | 正式 P95 |
|---|---:|---:|---:|---:|---:|
| **Qwen** | **83.3% → 94.4%** | **6.8% → 2.9%** | 8.3% → 3.3% | 58.3% → 83.3% | 92s |
| Doubao | 77.8% → 85.6% | 10.9% → 7.4% | 13.9% → 10.0% | 41.7% → 63.3% | 76s |
| DeepSeek | 80.6% → 90.0% | 8.1% → 4.8% | 11.1% → 6.7% | 50.0% → 73.3% | 111s |

Qwen 的端到端成功率提升 **11.1 个百分点**，工具失败率下降 **3.9 个百分点**。三个模型均有改善，说明校验与定向修复改善的是完整交付链路。

## 产品决策

| 策略 | 选择 | 判断 |
|---|---|---|
| 默认模式 | **Qwen** | 成功率和稳定性最高，质量/时延均衡 |
| 快速模式 | **Doubao** | 平均 43s、P95 76s，三者最快 |
| 高质量备选 | **DeepSeek** | 成功率 90.0%，但 P95 111s |
| 复杂任务 | **限制范围 / 异步执行** | 复杂 Excel、多产物会放大失败与长尾 |

这不是模型能力的普遍排名，只适用于本项目的任务集、Prompt、工具链和执行策略。

## 失败分类

- **模型理解失败：** 漏交付物、误解格式或约束 → 改 Prompt、澄清与计划。
- **工具执行失败：** 工具选错、参数无效、调用中断 → 改 schema、参数校验与重试。
- **产物生成失败：** 文件损坏、内容缺失、HTML 交互失效 → 改生成器与文件级校验。
- **校验 / 修复失败：** 未校验即交付、修复未命中根因 → 改交付门禁与错误反馈。
- **长尾 / 稳定性失败：** 少量运行异常慢或重复运行波动 → 改超时、异步与回归集。

## 项目价值

评测的最终目的不是“打分”，而是帮助产品决定：用哪个模型、在什么任务里用、哪些任务要限制、哪些问题该改 Prompt、哪些该改工具、哪些该改产品流程。

## 运行

```bash
python scripts/validate_results.py
python scripts/summarize_results.py
```
