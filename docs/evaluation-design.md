# 评测设计

## 目标与边界

本项目把一次完整运行作为评测单元：从接收任务，到 Word、PDF、Excel 或 HTML 成果通过校验并可交付。对象为 Qwen、Doubao、DeepSeek；结论仅适用于本任务集、Prompt、工具链与运行方式。

## 任务与运行

任务覆盖单一文档、结构化表格、交互页面、多产物和格式转换，分 easy / medium / hard。基线为 12 题 × 3 模型 × 3 次 = 108 次；正式为 30 题 × 3 模型 × 3 次 = 270 次。重复三次用于识别偶然成功。

基线使用 `生成 → 直接交付`。正式阶段加入：执行前提取全部交付物；交付前强制 `validate_artifact`；失败后允许一次定向修复；复检未通过则明确失败。

## 成功判定

只有所有指定交付物存在、可解析、格式匹配、关键结构通过程序检查、核心交互可用，且未在校验失败时宣称完成，才计为端到端成功。工具失败与产物失败可同时命中，不能用失败率简单相加反推成功率。

三次全成功率以任务为分母：同一模型对同题三次均成功才计入。P95 观察长尾，不与平均耗时互换。

## 机评、视觉复核与人评

程序校验负责文件存在、可解析、必需结构和控件；模型/视觉复核负责截断、层级和可读性；人工抽检判断成果是否真正可用并给出 A 档。机器门禁不替代人评，人评也不能掩盖文件打不开等确定性失败。

基线未记录平均耗时和人评 A，CSV 中保留为空，不补零。两阶段任务规模不同，结果用于方向性比较，不被表述为普遍因果结论。
